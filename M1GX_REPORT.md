# M1-GX Reconstruction Breakthrough Trial

**Status:** Experimental result; no default profile promotion.
**Source revision:** `02a67e8779889336a76bf04cbe4724c695d6511a` (the resumed worktree contained three modified Rust files for this experimental scaling path plus unrelated untracked research; the unrelated files were left untouched).
**Fixture:** frozen M1-G 8-page 300 DPI synthetic scan, 1,800 × 900 px per page, 432 × 216 pt; 552 non-space OCR occurrences and 48 spaces. The converter received degraded source pages plus OCR only. Pristine images/truth and licensed source outlines were available only to oracle arms and the evaluator.

## Result

The strongest integrated candidate is the existing M1-G canonical-experimental output (O4), not the experimental uniform-placement output (O5). It improves renderer-relative mean glyph IoU versus the same-renderer custom source-raster control by about 0.028 Poppler and 0.003 PDFium, reuses 32 distinct outline shapes across 289 accepted occurrences, and retains searchable text. It is only 77 bytes larger than the source searchable PDF. It is not a materially smaller document.

The oracle ladder says the reconstructed outline can be good when assigned the correct family and placed using pristine ink bounds (O2); the gap from that to actual inferred grouping/current placement (O4) is real. But replacing independent X/Y scaling with uniform scaling did not improve the real ScanWeave run: actual bbox IoU worsened from 0.9723 to 0.9651, and O5 rendered slightly worse than O4 in both engines. The trial therefore does not justify promoting that placement change.

Raster suppression is actually happening: 52,618 dark source samples were removed, with 288 added and no changed samples outside the 289 accepted occurrence boxes. Yet the raster stream remains 4,079,502 bytes, about 97.5% of O5. O5 is 304 bytes larger than frozen M1-G O4 and 381 bytes larger than the custom raster searchable PDF. Composition and residual page backgrounds, rather than the reusable font, now dominate size.

## Experimental arms

All arms are actual PDFs at 300 DPI. O0 through O3 and C0/C2 are custom research PDFs generated by `qualification/experiments/m1gx/trial.py`; O0 is a custom source-raster control, not a ScanWeave conversion. O2/O3 use C1, where accepted glyph interiors in the source page are replaced using evaluator-only pristine/background pixels and truth boxes. Their pairwise differences isolate the indicated outline/placement changes, but their absolute visual scores and file sizes are not end-to-end ScanWeave results. O4 is the frozen M1-G ScanWeave PDF; O5 is a fresh ScanWeave CLI conversion with an opt-in experimental uniform scaling flag. PDFium and Poppler rendered at the same 1,800 × 900 pixels per page. The comparison crops use a fixed source-truth coordinate frame; threshold sensitivity is retained in `300/gx_metrics.json`. Renderer scores are reported separately.

The oracle ladder isolates different things. O1 uses pristine source font geometry and image background, so its size is not a like-for-like background-compression comparison; Poppler scores above the source-rendered baseline but PDFium scores below it. O2 and O3a compare the same oracle-selected reconstructed forms under pristine target boxes versus inferred replacement boxes; in this fixture the difference is small (+0.0004 Poppler, +0.0006 PDFium), so placement extent contributes little under this corrected counterfactual. O3a and O3b compare oracle-selected and inferred outline identities under the same inferred replacement boxes, with each outline fitted using its own geometry. The oracle-family arm gains +0.0154 Poppler and +0.0093 PDFium over inferred assignment, making family/prototype assignment the clearest measured fidelity gap here. This is evidence about this fixture, not a general estimate of grouping performance. O2 remains reconstructed geometry: it selects the majority existing prototype for an oracle family, not a pristine outline.

The initial O2 placement accidentally targeted OCR crop bounds rather than pristine ink bounds; that run was invalidated and retained as `metrics-invalid-safety-box-oracle-placement.json`. An early predicted placement calculation was also invalid; actual PDF text matrices were parsed and checked in `actual-placement-check.json`. The current table is based on actual final output files; the final SHA and byte manifest is `300/run-manifest.json`. O3a’s affine is recomputed for the substituted outline using the current independent-axis fit and the same inferred replacement box; it no longer reuses the inferred form matrix.

## Placement and composition

The actual text matrices for 289 accepted occurrences give P0 current scaling a mean absolute center error of 0.204 px horizontally and 3.502 px vertically, mean width/height error of 0.313/0.393 px, and mean bbox IoU 0.97233 against pristine ink. The opt-in P1 uniform scaling gives 0.239/4.193 px center error, 0.382/0.541 px size error and 0.96507 bbox IoU. P1 therefore regresses actual placement. It is gated to `--profile canonical-experimental`; faithful mode defaults are unchanged.

The C0 double-paint arm is larger and worse than O0. C2 improves over C0 but is still below the O0 render in PDFium and slightly above it in Poppler. O5 page-image auditing finds 119,402 source dark samples (`<145`) and 67,072 output dark samples; 52,618 were removed, 288 added, and all 61,576 changed samples fell inside accepted boxes. Within accepted boxes, 54,613 dark source pixels fell to 2,283 output dark pixels; 1,995 dark samples remain. This verifies raster ink suppression in this synthetic fixture, not general-safe ownership or clean-background estimation.

## Reuse, semantics and visual evidence

There are 552 non-space observations. The run accepted 289 occurrences (52.4% of non-space occurrences, or 48.2% including spaces). The embedded font has 65 glyph programs; accepted placements reference 34 used GIDs and 32 distinct outline path hashes. There is one shared embedded TrueType font. For example, 60 accepted `a` occurrences across pages p00–p05 use a single identical canonical outline shape (59 through one GID and one through a second GID with the same path); 60 accepted `g` occurrences also reuse forms. The accepted output is not replacing every occurrence, and OCR provenance remains independent of the visual outline assignment.

Poppler and PDFium both extract 552 characters and match the supplied OCR sequence after removing whitespace. They do not match source truth order: one deliberate OCR confusion on page p07 reports `c` where source truth is `e` (1/552 CER). Text extraction success therefore demonstrates that the provided OCR layer survives, not that OCR is correct.

The scan-to-pristine raw glyph IoU averages 0.9452. Rendered O0 PDF IoU is 0.8546/0.8545 (Poppler/PDFium), reflecting renderer sampling and PDF image display; these scales are not averaged together. O4 improves on the custom O0 source-raster control by +0.0283 Poppler and +0.0029 PDFium, but O5 slips from O4 by −0.0023/−0.0032. Mean scores hide different examples: O4’s strongest paired repair is `p03s0073` (`?`, +0.238 Poppler and +0.107 PDFium relative to the rendered raster baseline); its worst is `p07s0003` (`0`, −0.362 in both). The 2,400 DPI PDFium crop sheet is `300/examples-best-and-worst-2400dpi.pdfium.png`; full page and diagnostic glyph crops are also retained in `300/`.

## Bytes, runtime and validity

O4 accounting: 4,079,502 raster bytes, 38,292 font bytes, 59,705 content bytes, 7,008 overhead bytes, total 4,184,507. O5: the same 4,079,502 raster bytes and 38,292 font bytes, 60,009 content bytes, 7,008 overhead, total 4,184,811. The converter’s same-run raster candidate is 4,213,289 bytes, so O5 saves 28,478 bytes (0.68%) against that candidate, while remaining slightly larger than O0/O4. Its 8 page images are full-resolution 1,800 × 900 grayscale streams. Raster bytes, not font programs, dominate.

The O5 report records 290.652 s total wall time, of which 274.883 s is page conversion and 7.796 s donor collection; font build takes 13 ms, PDF assembly about 4.1 s. Peak memory was not instrumented, so no memory claim is made. The page conversion cost remains the performance bottleneck; the experiment does not establish whether canonical reuse reduced tracing time versus a controlled repeated-tracing run.

All 11 experimental PDFs pass qpdf syntax checks; the O5 embedded font passes OTS and has 65 glyph programs. Poppler/PDFium extraction checks pass (whitespace-normalized text comparison). E0–E7 mechanical checks pass in the recorded run. The inherited P01–P08 visual gates remain failed; P08 also had a PDFium transport failure. These are listed separately in `300/e0-e7-results.json`. A raster-only fallback pixel-equivalence claim is not made: the inherited 300 DPI `8` case remains discrepant (source patch hash matches and transform is exact; A1 IoU 0.911/0.913 vs ClearScan patch 0.732/0.768, Poppler/PDFium; a diagnostic 1 px shift raises the latter to 0.822). This existing issue is isolated, not resolved by GX.

## Adobe comparison limit

The frozen Adobe XI outputs remain the M1-E three-page fixture, not this eight-page M1-G document. The 300 DPI Adobe ClearScan file is 46,213 bytes, SHA-256 `6d2150c05e1102cd90a3cdc48f87aeff08af118bf63a5390a787f909589258fb`; the 600 DPI file is 51,429 bytes, SHA-256 `86e26797a02d2e6688c38f8cf6c3f668842da854bcdc177437ce002b3382e6e2`. Those values are not compared as a same-input file-size or fidelity result. Adobe was not run on this fixture, and no GX Adobe quality claim is made.

## Conclusion and next step

The experiment demonstrates the mechanism end to end: multiple page observations feed canonical outlines, 289 raster text occurrences are replaced and source ink is suppressed at those locations, and the text remains searchable. It does not demonstrate the product objective of a materially smaller PDF. The clearest fidelity limitation is inferred glyph-family/prototype assignment: oracle selection improves O3a over O3b by +0.0154/+0.0093 mean IoU. The separate size limitation is residual full-page raster payload (97.5% of O5 bytes), and the page-conversion stage dominates runtime. The tested uniform-placement correction regressed and should not be promoted. Prioritize a bounded fix to assignment for glyph fidelity; any subsequent size work must reduce residual background bytes while preserving the measured ownership boundaries. Do not change the stable faithful profile.

No 600 DPI GX rerun was made because the corrected 300 DPI P1 placement did not improve. No consensus or complementary-no-perfect-donor experiment was run; this round stayed on the existing frozen M1-G observations and did not establish that adding witnesses improves outlines. The current fixture is mostly healthy or moderate (345 healthy, 204 moderate, 3 heavy), so conclusions about heavily damaged text are limited. No genuine receipt/book sample was used. The sealed holdout was not opened.

## Independent review

The independent review identified stale outputs, asymmetric renderer resizing, incomplete placement isolation, weak OCR-ground-truth separation and a globally available experimental flag. The GX harness now rerenders every PDF for measurement (including O4), crops PDFium's one-pixel excess without resampling, records actual matrix checks and separately recomputes oracle-form current placement, reports source-text mismatch, and gates uniform scaling to the experimental profile. Final review also caught and corrected the O4/O0 byte arithmetic and required a narrower identity interpretation.

## Reproduction

From repository root, with the qualification virtualenv and tool environment installed:

```sh
qualification/.venv/bin/python qualification/experiments/m1gx/trial.py
GX_RENDER_SET=final3 qualification/.venv/bin/python qualification/experiments/m1gx/measure.py
qualification/.venv/bin/python qualification/experiments/m1gx/actual_placement_check.py
qualification/.venv/bin/python qualification/experiments/m1gx/background_audit.py
qualification/.venv/bin/python qualification/experiments/m1gx/high_zoom_render.py
qualification/.venv/bin/python qualification/experiments/m1gx/validate_pdfs.py
cargo test -p scanweave-cli -p scanweave-io
```

O5 is produced from the tracked M1-G bundle with `--mode reconstruct --profile canonical-experimental --glyph-dictionary visual --gx-uniform-glyph-scale`; the report JSON and exact command are recorded in the run manifest. The opt-in flag only tests uniform scaling; the default placement remains the current independent-axis behavior.
