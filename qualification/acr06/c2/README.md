# ACR-06 C2 reproduction

The inputs are the already-opened files under `/data/coding/scanweave/qualification/font04/local` and the two packaging inputs. `run.py` writes all outputs to `/data/coding/scanweave/qualification/acr06/local/c2`. It never creates or opens a new holdout. The requested list has 38 documents, not 41.

Build this branch and copy its release executable to `/tmp/c2-research-scanweave`. Build base `79b30e5` in a separate source/target directory and copy that executable to `/tmp/c2-main-scanweave`. `identity.py` generates the clean-base comparison. Run `run.py /tmp/c2-research-scanweave`, then `analyze.py`, `numeric.py`, `functional.py`, and `panels.py`. Run `runtime.py` one process at a time after every other study process finishes, then copy `runtime/results.json` to this directory and run `report.py`. The corpus runner can be restarted: a `.done` marker is written only after a successful conversion.

The Python evaluation environment used numpy 2.5.4, Pillow 13.0.0, pikepdf 10.17.0, pypdfium2 5.14.0, scipy 1.18.1, and fonttools 4.68.0. The bundled `pypdfium2_raw/libpdfium.so` was replaced by a symlink to `/data/coding/scanweave/tools/src/pdfium/lib/libpdfium.so` (SHA-256 `b8784cbd652ad2993332b7695e2c80f3a797f877fc47d9be97b66bca9639539e`). `pr26_metrics.py` is copied unchanged from `research/font04-document-fonts:qualification/font04/metrics.py` and is used by the numeric and panel scripts. Poppler's `pdftoppm` and `pdftotext`, the repository's qpdf, and OTS are also required.

`SCANWEAVE_RESEARCH_OWNERSHIP=trace` requires `SCANWEAVE_RESEARCH_OWNERSHIP_TRACE` to name the separate trace JSON; `corrected-only` changes only the q3 ownership veto. Unset retains the normal decision. All comparisons use the saved PR #26 q3 and off outputs as specified in the ledger, and the scripts preserve the existing inputs read-only. The three clean-main SHA comparisons were independently produced by `identity.py`.

The parallel supplementary dispatcher was stopped after its P2′ sheet-8 conversions completed to prevent a second dispatcher from writing the same later output paths. Both output logs reported successful writes, and qpdf checks and sidecar/trace JSON parsing were used to validate those two completion markers. During setup, the first functional pass lacked qpdf's shared-library path; it was discarded and the entire functional pass was restarted with `tools/dist/lib` on `LD_LIBRARY_PATH`.
