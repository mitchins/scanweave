# Pilot measurement conventions and limits

Diplomatic text scoring preserves case, long-s and ligatures and collapses whitespace. Reading scoring folds long-s to `s`, applies Unicode NFKC (including compatibility ligature decomposition), removes a hyphen followed by a line break and surrounding whitespace, case-folds, then collapses whitespace. These are the reading operations called for in BOOKS-01 and align in intent with the named FineBooks evaluator; that evaluator's implementation was not downloaded or independently audited here. They are not claimed to be a byte-for-byte port.

Character distance is unit-cost Levenshtein. A U+FFFD in GT matches one arbitrary hypothesis character at zero substitution cost; it is excluded from the known-character denominator and deletions remain edits. Word distance is unit-cost Levenshtein on whitespace tokens; U+FFFD matches one character within its GT token. GT tokens containing a wildcard are excluded from the known-word denominator. CER and WER can exceed 1. Bag recall counts known reference characters without order. OCR text is the selected frozen hOCR word sequence. These scores mix recognition and ordering effects; PDF extraction and visual scores are reported separately.

PDFium search is literal and case-insensitive on 20 unique reading-normalized GT terms of at least four characters, and 20 terms drawn from the other five pilot pages, using a page-specific SHA-256-derived seed. It does not normalize the PDF text layer for ligatures or long-s. Shortage of terms is reported via the actual denominator. Search terms are stored only as hashes.

Layout groups PDFium character boxes by vertical centre; this deliberately simple grouping can merge columns. Greedy matching uses rasterized GT polygon versus predicted rectangle IoU >= 0.5. FineBooks uses only TextRegions containing a single text line as proxies; all other FineBooks regions stay region-level. Reading-order tau covers exact normalized GT matches only; its match count must accompany it. Duplicate-line detection is a heuristic, not proof of duplicated text.

Visual metrics compare each output to the source PDF rendered by the same engine. Poppler uses `-cropbox` to match PDFium and MuPDF page boundaries. If dimensions differ by one pixel due to page-size rounding, only the common top-left pixel rectangle is compared and both original and compared dimensions are recorded; no image file is modified. Regions use GT TextRegion polygons, Image/Graphic/Chart polygons, and remaining paper. Overlap is assigned to illustration. Grayscale SSIM uses the scikit-image default window and a data range of 255; ink is PIL grayscale < 128. L* differences use CIE luminance; illustration colour uses CIEDE2000. Ink recall and precision report actual denominators implicitly through the mask and are undefined when the denominator is zero.

The detector thresholds are pilot-derived triage aids, not proof of a wrong glyph. Word boxes come from selected frozen hOCR; contour overlap, chamfer and missing/spurious ink are measured against the source. Illustration and border detectors use fixed tiles. The top two per detector and two random non-top word-box controls per page form a blinded crop set at 4x nearest-neighbour enlargement. The source is labelled; output labels are freshly shuffled per crop. Every candidate is suspected until independent human adjudication. Raw per-row scores and the label key remain local and outside the blind pack index.
